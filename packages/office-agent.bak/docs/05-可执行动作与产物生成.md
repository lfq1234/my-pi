# 05：可执行动作与产物生成

## 背景

04 的目标是把 Office 文件真正解析出来，05 的目标是把这些解析结果转化为实际可执行动作。也就是说，agent 不再只是“读文件”和“总结文本”，它要能够直接生成多种 Office 相关的产物。

这个阶段要解决的问题是：

- 读取 Word / Excel / PPT
- 自动生成摘要
- 生成 HTML 页面
- 生成邮件正文
- 生成海报 prompt
- 输出可交付文件

## 核心思想

05 不是增加一堆通用 AI 能力，而是把“读取 + 生成 + 输出”串成闭环。也就是说：

输入 Office 文件 -> 抽取内容 -> 补充结构 -> 生成成果物 -> 写出到输出目录

## 目标场景

### 1. 读取 Word，生成总结

输入：

- .docx file

输出：

- 文档 summary
- 重点章节
- 可嵌入汇报的文字
- 供后续生成 HTML or email 的内容

### 2. 读取 Excel，生成统计图/汇报

输入：

- .xlsx

输出：

- 数据聚合结果
- KPI summary
- 报表说明文案
- 统计图 prompt

这里的核心不只是读取表格，而是“把数据转成决策信息”。

### 3. 读取 PPT，生成会议纪要

输入：

- .pptx

输出：

- 会议纪要
- 关键结论
- 待办事项
- 下一步行动项

### 4. 生成 HTML 页面

输出：

- report.html
- preview.html
- index.html

目标是让结果能直接打开查看，适合业务汇报和手工审核。

### 5. 生成邮件正文

输入：

- summary
- audience
- tone

输出：

- 标题
- 正文
- 发送对象
- 发送场景（汇报、提醒、通知、会议邀约）

### 6. 生成海报 prompt

输出：

- title
- visual theme
- style
- layout suggestion
- image generation prompt

这个可以直接喂给 Seedance 或其他图像模型。

### 7. 直接写出 Office 文件

支持输出：

- .docx
- .xlsx
- .pptx

如果没有真实 Office 引擎，也先让系统支持结构化输出和模板生成，后续再接真实写库。

## 执行链路

```text
文档输入
  -> 解析文件
  -> 提取结构
  -> 机构化 summary
  -> 生成 report / email / poster
  -> 输出 HTML / email text / data file
  -> 可选：写出 Office 文件
```

## 设计要求

### 1. 产物统一命名

输出目录结构建议：

```text
.office-agent-output/
  run-20260814-123456/
    report.html
    preview.html
    summary.md
    email-draft.md
    poster-prompt.txt
    assets/
      chart.png
      poster.png
    docs/
      generated-report.docx
      data-summary.xlsx
```

### 2. 生成器分层

建议按下面方式拆：

- content extractor
- summarizer
- html generator
- email generator
- poster generator
- office writer

这样每一个动作都可以单独测试。 

### 3. 失败兜底

当某个生成动作失败时，必须：

- 不中断其他步骤
- 保证历史产物保留
- 日志记录失败原因
- 生成 fallback 文案

## 重要原则

- 产物生成必须依赖标准结构化输入
- 不要让 HTML、邮件、海报生成器直接读原始 Office 文件
- 统一抽取器是前提，工作流层是后续
