# 00. 产品概览与架构规划

## 1. 项目愿景

Office Agent 的目标，是在 Pi 的 agent runtime 基础上，打造一个面向办公场景的生成型与执行型助手。它不只是回答问题，而是能够：

- 读取办公文件
- 提取关键信息
- 生成结构化内容
- 输出 HTML/展示页
- 生成海报类图片
- 生成邮件草稿与协同内容
- 按需将结果保存到本地或外部平台

最终目标是让用户可以通过一个统一入口快速完成办公内容生产任务，而不是手动在多个工具之间来回切换。

## 2. 适用场景

### 2.1 文档整理与汇总

- 读取多个 PDF、Word、Markdown 文件
- 提取会议要点、任务、统计结论
- 输出一份汇报摘要或行动列表

### 2.2 报告与演示输出

- 输入会议纪要、调研材料、项目资料
- 自动生成 HTML 报告页或汇报页面
- 提供可浏览、可分享、可导出的静态页面

### 2.3 海报与营销素材生成

- 输入活动主题、目标受众、文案要点
- 调用 Seedance 等图像生成模型
- 生成海报候选图，供用户精选和使用

### 2.4 邮件协同

- 读取已有邮件或任务上下文
- 自动生成邮件标题、正文与要点
- 提供草稿确认流，再决定是否发送

### 2.5 日常办公流

- 读取 Excel/CSV 或表格数据
- 生成总结页、图表说明、行动建议
- 自动生成可复用模板输出

## 3. 产品定位

这不是“代码 agent”的延伸，而是一个平行的办公类 Agent 产品，具备以下特征：

- 任务型：更偏生成与整理，而不是泛聊天
- 工具型：依赖真实办公工具和外部服务
- 审批型：动作之前先让用户确认，降低风险
- 可视化：结果输出为 HTML、Markdown、文档草稿和图像

## 4. 核心能力拆解

### 4.1 Office 读取

支持以下内容读取：

- PDF
- Word (.docx)
- Excel / CSV / TSV
- PowerPoint / PPTX（至少提取文本与标题）
- Markdown / TXT / HTML

能力包括：

- 文本抽取
- 标题/段落结构识别
- 关键结论提取
- 表格数据识别
- 多文档摘要合并

### 4.2 Office 写入

支持输出的内容类型：

- Markdown
- HTML
- TXT
- JSON 元数据
- 可选：CSV/Excel 导出

能力包括：

- 保存总结结果
- 生成报告草稿
- 自动写回本地目录
- 生成供后续与 UI 绑定的文档对象

### 4.3 HTML 生成

输出目标：

- 汇报页
- 周报页
- 竞品分析页
- 海报展示页
- 企业公告页

核心需求：

- 支持单页布局
- 支持标题、摘要、卡片、图表区块
- 支持图片、表格、列表
- 支持适度样式定制
- 能输出到本地文件或内存模板对象

### 4.4 海报生成

目标：

- 根据主题生成海报视觉稿
- 结合文案和图像返回可用的海报素材
- 允许用户在网页端进行筛选和二次修改

技术路径：

- 调用 Seedance 等图像模型生成图像
- 生成候选图集合
- 按内容 + 风格参数生成海报图
- 组装到 HTML 页面中进行展示

### 4.5 邮件接入

目标：

- 读取邮件上下文
- 生成邮件标题、正文和发送建议
- 让用户审阅后再决定是否发送

支持形式：

- SMTP
- Microsoft Graph API
- Gmail API
- 兼容本地测试草稿模式

## 5. 系统架构

Office Agent 应保持与现有 Pi monorepo 一致的分层结构：

### 5.1 基础层

- AI 模型层：复用 packages/ai
- Agent runtime：复用 packages/agent
- session / state：复用 packages/session-backends
- telemetry：复用 packages/telemetry

### 5.2 办公能力层

- office tools
  - read-office
  - write-office
  - generate-html
  - generate-poster
  - email-tools
- workflow orchestration
  - report pipeline
  - poster pipeline
  - email pipeline

### 5.3 表现层

- Web UI：网页端交互面板
- CLI/terminal：作为调试和开发入口
- 结果预览：HTML 页面预览、海报卡片、邮件草稿

### 5.4 外部集成层

- 文档处理库：PDF、Word、Excel、PPT
- 图像生成：Seedance
- 邮件服务：SMTP、Graph API
- 存储：本地文件、对象存储、数据库

## 6. 建议的技术栈

### 6.1 后端

- TypeScript / Node.js
- 从当前仓库复用 Pi agent runtime
- 统一 AI 模型接入
- 本地持久化 session 数据

### 6.2 读取与处理

- PDF 解析器：pdfjs 或，必要时 pdf-parse / Mammoth / xlsx
- Word 解析：mammoth
- Excel 解析：xlsx
- PPT 解析：尚可优先抽取文本或使用 pptx-parser

### 6.3 HTML 生成

- 模板引擎：自研模板 + 简单 HTML 拼装
- 也可用 EJS / Handlebars / React SSR，优先选择轻量方案

### 6.4 图像生成

- Seedance API 调用
- 生成 prompt + style params + 输出路径
- 生成前做统一模板参数结构，后续便于扩展

### 6.5 网页前端

- 可先用轻量 HTML/JS 页面快速实现
- 后续再考虑 React 或 Vue
- 目标是快速演示和收敛产品能力

## 7. 架构原则

### 7.1 Tasks 不是 Chat

Office Agent 的核心任务不是自由聊天，而是任务化执行：

- 读取资料
- 筛选内容
- 产出结果
- 生成草稿
- 用户确认

### 7.2 统一输入输出模型

每个工具都应该定义统一结构：

- 输入参数
- 输出数据
- 成功/失败状态
- 产物路径
- 生成内容摘要

### 7.3 审批优先

对真正执行的动作（发邮件、写文件、保存草稿、生成海报）都要有确认步骤。

### 7.4 可检测性

每个工具执行必须产生：

- 操作时间
- 触发来源
- 引用材料
- 产物输出
- 失败原因

## 8. 非功能需求

### 8.1 安全性

- 关闭危险自动执行前置默认开关
- 任何外部写操作都要求二次确认
- 设置输出目录白名单
- 对邮件发送和外部 API 调用做权限区分

### 8.2 可观测性

- 工具调用日志
- 产物生成状态
- 邮件草稿状态
- 图像生成状态
- 生成失败原因和重试次数

### 8.3 可扩展性

- 增加新工具时要符合统一 tool schema
- 工具可按能力分组，不强耦合
- 支持新增生成模板和数据源

## 9. 风险点

### 9.1 读取能力不稳定

Office 文件解析标准不统一，不同格式可能导致内容提取不准。

对策：

- 先支持最稳定的格式：PDF、TXT、Markdown、CSV
- 对复杂 Office 文件做最佳-effort 提取
- 降低自动写入门槛

### 9.2 生成内容可能不符合要求

文本生成和图片生成可能偏离目标风格。

对策：

- 增强模板约束
- 增加 prompt 规范
- 让用户在网页里进行二次编辑

### 9.3 自动发送风险高

邮件发送和写文件等行为很危险。

对策：

- 默认必须人工确认
- 支持 dry-run
- 所有动作留下日志

## 10. 先做什么，后做什么

### 先做

- Office 文件读取
- Markdown/HTML 输出
- 生成 HTML 报告页
- 基本邮件草稿生成
- Seedance 图像生成接入

### 后做

- 真实邮件发送集成
- 复杂 Excel 规则处理
- 数据导出和模板化工作流
- 企业权限和多租户升级

## 11. 总结

Office Agent 的核心价值不在于“智能聊天”，而在于“把办公内容处理流程变成可执行的 Agent 工作流”。

最重要的能力是：

- 读取真实材料
- 抽取结构化信息
- 生成高质量办公产物
- 让用户能审阅并确认执行

这也是其真正与泛聊天机器人区分的地方。
