# 03. 增强版真实集成与预览闭环

## 1. 目标

在 00/01 的基础上，03 版本重点将 Office Agent 从“可演示的工作流”升级为“能真实处理办公素材、生成可预览产物，并具备外部服务集成能力”的增强版实现。

核心目标包括：

- 真实增强 Office 文档解析：支持结构化文本、表格、标题、段落抽取
- 完整 HTML 模板：加入汇报页、关键结论、图片区、行动项、文档列表
- 真接入 Seedance：让图片生成具备标准请求/响应契约，并支持本地回退
- 真接入邮件发送：支持 webhook / SMTP / Graph 形式的统一接口层
- 提供 Web 预览页：让 HTML、邮件草稿、海报内容在浏览器中可直接查看

## 2. 设计原则

### 2.1 先做真实闭环，再做“智能”扩展

03 阶段不追求功能无限扩展，而是要实现一条稳定的生产链：

输入 office 文件 -> 解析文本 -> 生成摘要 -> 生成 HTML -> 生成海报提示词 -> 可选生成图 -> 生成邮件草稿 -> 输出可预览网页

这条链路对 Office Agent 来说是高价值且具备展示效果的最小闭环。

### 2.2 所有动作都要有明确接口

即使是“真实接入”，也要保持清晰的边界：

- 读取层只负责从文件中抽取内容
- 报告层负责整理结构
- 生成层负责 HTML / 邮件 / 海报
- 预览层负责装配展示页
- 集成层负责安全调用外部服务

### 2.3 支持降级和回退

真实服务可能失败、无密钥、无网络、无权限，必须具备优雅回退：

- 无 Seedance API Key 时返回草稿状态
- 无邮件服务配置时返回“已准备发送任务”而不是直接失败
- 解析失败时保留原始内容并附加警告

## 3. 功能拆解

### 3.1 真实 Office 文档解析增强

目标：把“placeholder 文本”升级为“结构化读取”。

支持能力：

- Markdown / TXT / HTML：按标题、段落、列表做结构化提取
- CSV / TSV：转成表格摘要，并保留字段名与数据样本
- PDF / DOCX / XLSX / PPTX：初期优先抽取文本标题与摘要，保留原始预览
- 多文件汇总：将多个文档作统一摘要，避免摘要失真

设计：

- 新增结构化解析器：extractDocumentStructure()
- 统一返回：title, summary, sections, warnings, rawText
- 能输出到 HTML / Markdown / JSON 的中间结构

### 3.2 HTML 模板增强

目标：从“简单纯文本页面”升级为“报告型页面”。

新增模块：

- 页头：标题/日期/状态
- 摘要卡片：核心结论
- 文档概览：文件列表、类型、摘要
- 关键结论区：bullets / actions
- 海报区：可插入生成图
- 邮件草稿区：可预览邮件主题与正文

输出：

- report.html：报告页
- preview.html：完整预览页

### 3.3 Seedance 真接入

目标：把海报生成接口从纯提示词模板变成可调用的服务层。

统一接口：

```ts
interface SeedanceGenerationRequest {
  prompt: string;
  style?: string;
  ratio?: "1:1" | "3:4" | "4:5" | "16:9";
  seed?: number;
}
```

返回：

```ts
interface SeedanceGenerationResponse {
  prompt: string;
  style: string;
  ratio: string;
  status: "draft" | "generated";
  imageUrl?: string;
  localPath?: string;
}
```

行为：

- 有 API Key 时尝试 POST 到 Seedance endpoint
- 无 API Key 时返回 draft 状态并保留提示词
- 若网络失败则记录错误并回退为草稿

### 3.4 邮件真发送接口

目标：从“生成草稿模板”升级到“可调用发送层”。

统一接口：

```ts
interface SendEmailRequest {
  to: string;
  subject: string;
  body: string;
  provider?: "mock" | "smtp" | "graph" | "webhook";
}
```

支持行为：

- mock：本地草稿，不真实发送
- webhook：向自定义 endpoint 发送 JSON
- smtp / graph：预留真实接入入口，后续落地

### 3.5 Web 预览页

目标：让结果能直接打开浏览器查看，不仅靠命令行输出。

要素：

- 页面标题
- 概要摘要
- 文档列表和每个文件的摘要
- 关键结论
- 海报卡片位置
- 邮件草稿正文栏
- 操作按钮：打开 HTML、复制文本、保存附件

## 4. 关键数据结构扩展

在 03 阶段建议增加以下结构：

```ts
export interface OfficeDocumentSummary {
  title: string;
  summary: string;
  sections: Array<{ title: string; content: string; bullets?: string[] }>;
  warnings: string[];
}

export interface PreviewArtifact {
  html: string;
  path: string;
}
```

这样能把“文本解析”和“展示层”从一开始就拆清楚，后续方便扩展到真实 PDF / Word / Excel 解析器。

## 5. 实施顺序

### 第一步：结构化文档解析增强

- 抽取标题
- 抽取段落
- 抽取列表和关键句
- 处理 CSV 表格摘要
- 为多文件汇总准备数据对象

### 第二步：增强 HTML 模板

- 增加正文区块和 action list
- 增加文件列表区块
- 增加海报位置和邮件草稿区

### 第三步：服务层接入

- SeedanceClient
- EmailClient
- 统一错误处理和回退逻辑

### 第四步：Preview 页面

- 生成 preview.html
- 允许浏览器直接打开
- 把邮件、海报、摘要装在一个页面里

## 6. 风险与控制

### 6.1 解析精度风险

不同 office 文件的结构不一致，所以要先做“可解释的文本结构抽取”，避免过早假定某种文件类型一定能解析完整。

### 6.2 外部服务依赖风险

Seedance 和邮件服务都可能有网络、密钥、权限问题，所以必须有：

- 回退状态
- 错误日志
- 用户确认机制

### 6.3 预览页过大

不要把所有原始二进制内容塞进 HTML；只保留摘要、结构化文本、关键图和可视化卡片。

## 7. 03 阶段验收标准

完成 03 后，至少满足：

- 能读取多个文本类办公文件并输出结构化摘要
- 能生成一份完整的 HTML 报告页
- 能生成完整预览页 preview.html
- Seedance 接口具备真实请求/回退机制
- email client 具备 provider 抽象和真实发送接口
- 结果可在浏览器中直接打开

## 8. 适用场景

03 的实现适合以下办公动作：

- 周报与月报汇总
- 会议纪要生成
- 活动海报概念页
- 市场报告输出
- 客户邮件跟进草稿生成

这正是 Office Agent 的核心价值区间。
