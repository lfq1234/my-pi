本文档用于记录 Office Agent 的设计、阶段目标、技术路线和执行计划。该项目以“办公协作型 Agent”为核心，目标是复用现有 Pi monorepo 的 AI Agent 基础能力，提供一个面向办公场景的产品能力，重点覆盖：

- Office 文件读取
- Office 文件写入
- HTML 报告/页面生成
- 海报图像生成
- 邮件协同
- 文档内容复用与汇总

## 项目定位

Office Agent 不是单纯的聊天机器人，而是一个具备以下能力的办公工作助手：

- 能读取 Office 文件与企业资料
- 能理解业务上下文并抽取关键信息
- 能生成高质量的办公内容，如汇报页、海报、邮件草稿
- 能将生成物落回文件系统或外部服务
- 能适度执行动作，并给出确认流，减少误操作风险

## 目标用户

- 企业内部文档整理人员
- 销售/运营/市场人员
- 会议纪要与汇报撰写人员
- 需要快速生成 HTML 页面、海报、邮件的人

## 设计原则

1. 以真实办公场景为核心，不追求“无所不能”的泛聊天机器人。
2. 以工具调用为核心，所有动作都要显式、可审计、可回退。
3. 先做高价值、低风险的功能闭环，再扩展更多工具。
4. 保留审查和确认步骤，减少误操作。
5. 尽量复用现有 Pi 的 agent runtime、AI 驱动、session 持久化与 telemetry 能力。

## 核心能力规划

### 第一阶段（MVP）

- Office 文件读取：PDF、Word、Excel、TXT、Markdown
- 写入能力：生成 Markdown/HTML/文本文件并保存
- HTML 页面生成：生成静态页面、汇报页面、展示页
- 海报制造：调用 Seedance 生成图像，供汇报页或海报页使用
- 邮件草稿生成：基于上下文生成邮件正文和标题

### 第二阶段（增强）

- 真实邮件系统集成：Outlook/SMTP/Graph API
- 文档模板化生成：周报、汇报、会议纪要
- 任务流管理：会议纪要 -> action items -> 邮件跟进
- 企业知识库接入：Notion、Confluence、wiki、文档库

### 第三阶段（平台化）

- 统一工作流编排
- 角色/权限控制
- 审计日志与回滚
- 多租户/多团队能力

## 关键限制

- 初期不追求无限制自动执行，避免办公误操作。
- 生成图像与邮件发送的真实执行具备明确授权流程。
- 文件读取、写出、生成 HTML 均要引入安全边界和输出校验。
